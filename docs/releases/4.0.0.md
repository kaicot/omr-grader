# OMR Grader 4.0.0

상태: 로컬 배포 후보(빌드 번호 25). main 병합과 push 전입니다.

[2.1.3](2.1.3.md)의 화면, 세션 저장, 채점, Excel 내보내기, 백업·복구는 그대로 두고 답안
인식 엔진(v4)을 바꾼 버전입니다. 포터블 경로, 배포 형식, receipt 형식 2와 검증 절차는
[2.1.1](2.1.1.md)과 같습니다. 설계와 합격 기준은 [v4 계획](../v4/v4-plan.md)에 있습니다.

## 바뀐 점

- **양식 자동 인식.** 스캔을 고르면 인쇄된 동그라미로 학번 칸과 문항 블록을 찾아 양식을
  정합니다. 처음 보는 양식은 "학번 8자리 · 객관식 50문항"처럼 요약과 미리보기를 한 번
  보여 주고, 확인하면 `Profiles\자동양식_객관식<문항 수>문항_<6자리>.omrtemplate`로
  저장합니다. 다음부터는 같은 양식을 자동으로 고릅니다. 저장된 양식은 확인한 장들이 모두
  믿을 수 있게 맞고, 그 장들로 새로 만든 양식만큼 정밀하게 맞을 때만 다시 씁니다. 그래서
  v3에서 손으로 그린 프로필은 자동으로 고르지 않고 새 양식을 만들어 확인을 받습니다. 표지나
  다른 양식의 장이 앞쪽에 섞여 있어도 저장된 양식을 다시 쓰고, 양식이 달라 보이는 장 수를
  알려 줍니다. 인식하는 동안 프로필을 직접 고르면 그 선택을 그대로 씁니다. 50번까지
  객관식이고 나머지가 주관식 칸인 양식은 객관식 부분만 인식합니다. 문항 블록 위에 ①~⑤
  동그라미 머리글 줄이 인쇄된 양식은 그 줄을 문항으로 세지 않습니다. 한 장만으로는 번호
  칸이 비어 있는 머리글만 알아보고, 3장 이상이면 어느 답안지에서도 칠해지지 않은 블록 맨
  윗줄을 머리글로 봅니다. 이렇게 뺀 줄이 있으면 확인 창에 알립니다.
- **장마다 인쇄된 동그라미에 맞춘 정렬.** 종이 가장자리 대신 각 장의 동그라미 수백 개에
  맞춰 기울기, 크기, 위치와 90°·180° 회전을 함께 보정합니다. 위아래는 인쇄된 ①이 ⑤보다
  분명히 옅게 찍히는지로 가리고, 동그라미 안에 숫자가 없는 양식은 문항 번호 위치로
  가립니다. ①이나 ⑤가 칠해진 줄은 비교에서 빼므로 거의 모든 문항에 ①을 칠한 답안지도
  뒤집혀 읽히지 않습니다.
- **마킹 판정.** 인쇄된 원 반지름의 0.75배 안쪽에서 주변 종이보다 얼마나 진한지 잽니다.
  같은 열에서 칠하지 않은 칸의 수준을 빼므로 진하게 인쇄된 숫자나 프린터 차이에 덜
  흔들립니다. 기본 감도 5에서 0.24 이상은 표시, 0.11 이하는 빈칸, 그 사이는 '확인
  필요'입니다. 감도 한 단계는 표시 기준을 0.012씩 바꿉니다.
- **추측하지 않는 안전장치.** 다음 장은 모든 답과 학번을 '확인 필요'로 보냅니다. 확인
  필요인 답은 검토에서 정하기 전까지 채점하지 않습니다.
  - 정렬이 약한 장: 맞은 동그라미 65% 미만, 또는 다른 방향 후보와 차이 5% 미만
  - 거꾸로 읽히는 장
  - 양식보다 동그라미가 많이 인쇄된 장(양식에 없는 동그라미가 양식 동그라미 수의 20%
    초과): 예를 들어 50문항 양식으로 읽는 묶음에 섞인 100문항 답안지
  - 양식의 한 영역을 한 칸(행이나 열) 옮기면 인쇄된 동그라미에 더 잘 맞는 장: 예를 들어
    한 블록이 한 칸 밀려 그려진 프로필로 읽은 장
- **정답표와 양식 대조.** 정답표에 답안지 양식에 없는 문항이 있으면 채점을 멈추고
  "정답표의 51~100번 문항은 답안지 양식에 없습니다"처럼 알립니다. 답안지 한 장에라도 그
  문항이 없으면 멈춥니다.
- **채점 이미지.** 깨끗한 스캔 위에 다음만 그립니다. 칸 상자와 글자는 그리지 않습니다.
  - 맞힌 답: 굵은 파란 원
  - 틀린 답: 고른 칸에 굵은 빨간 원, 정답 칸에 가는 파란 원, 문항 번호에 빨간 빗금.
    0점으로 확정되는 미응답과 중복 표기도 같습니다.
  - 확인 필요: 주황 원
- 템플릿 생성 도구는 더 필요하지 않습니다. 이전 판독 엔진(종이 가장자리 정렬, 정렬
  재시도, 방향 점수)은 제거했습니다.

### 기존 검증

- 전체 테스트: 1,435 통과, 12 건너뜀, 3 실패. 실패 3건은 이 PC에서 2.1.x부터 실패하던 환경
  문제입니다: 화면 배치에 따른 창 크기 시험 2건(`test_fit_clamps_*`), 한글 컴퓨터 이름 때문에
  권한 명령이 실패하는 ACL 시험 1건.
- ruff, mypy: 문제 없음.
- 독립 검토(별도 모델)에서 나온 높음 2건, 중간 2건, 낮음 여러 건을 고치고 시험을 더했습니다.
- 포터블 폴더 검증(`-Smoke Both -StrictShutdown`)은 이 문서를 커밋한 뒤 빌드에서 실행합니다.

## 알려진 한계

- 판정 기준값은 이 시험 두 파트와 예전 스캔의 분포를 보고 정했습니다. G4 예전 스캔도
  개발 중 원인 분석에 한 번 썼으므로 완전히 처음 보는 자료는 아닙니다. 다음 실제 시험의
  첫 채점에서는 채점 이미지 몇 장을 직접 확인하세요.
- 정답 데이터는 종이 원본과 대조하지 않았습니다.
- 지원하는 양식은 학번 8자리(8열 × 0~9), 보기 5개, 1번부터 이어지는 100문항 이하입니다.
  다른 양식은 양식 인식 단계에서 이유를 보여 주고 멈춥니다.
- 동그라미 안에 숫자도 없고 문항 번호도 인쇄되지 않은 양식은 위아래를 가릴 단서가 없습니다.
  새 양식 확인 창의 미리보기가 바로 서 있는지 확인하세요.
- 문항 번호는 왼쪽 세로 띠부터 위에서 아래로 매깁니다. 블록을 가로 방향으로 번호 매긴
  양식은 번호가 어긋날 수 있습니다. 새 양식 확인 창의 문항 범위(예: 1~20, 21~40)와
  미리보기의 번호를 확인하세요.
- 머리글 동그라미 줄의 번호 칸에 글자나 표 선이 있는 양식을 1~2장으로 처음 인식하면 머리글이
  1번으로 잡혀 문항 수가 블록마다 하나씩 늘어납니다(예: 53문항, 1~21). 처음 인식은 3장
  이상으로 하고 확인 창의 문항 수를 확인하세요.
- 반대로 3장 이상 모든 답안지에서 블록의 첫 문항이 비어 있으면 그 줄을 머리글로 보고 뺍니다.
  이때는 확인 창에 뺀 줄이 표시되고 문항 수가 하나 줄어듭니다(예: 99문항).
- 10°보다 많이 기울어진 장은 양식을 찾지 못한 장으로 처리합니다.
- 주관식 점수 입력, 채점 이미지의 점수·범례 머리글, 150 DPI 미만 이미지 경고, 빈 양식
  PDF로 양식 등록은 다음 버전으로 미뤘습니다.

## 운영 안내

- 감도는 기본값 5를 권합니다. v3에서 감도를 9로 올려 쓰던 설정을 그대로 가져왔다면 5로
  되돌리세요. 높은 감도에서는 지운 자국이나 얼룩이 답으로 읽힐 수 있습니다.
- v3에서 쓰던 포터블 폴더에서 처음 스캔하면 새 양식 확인 창이 한 번 뜹니다. 예전 프로필
  (예: `Tmot_OMR100.omrtemplate`)을 직접 고르면 읽기는 되지만 '확인 필요'가 크게 늘 수
  있습니다. 이번 시험 파트1에서는 12장 중 2장이 통째로 검토로 갔고, 자동 인식 양식으로는
  모두 자동 판독되었습니다. 자동 인식 양식을 쓰세요.
- 자동 저장된 양식 파일은 프로그램이 관리합니다. 이름을 바꾸거나 직접 편집하지 마세요.
- 기존 v3 시험 기록은 그대로 열리고 재채점됩니다. 재채점은 저장된 판독 결과를 쓰므로
  새 엔진으로 다시 읽지 않습니다. 2.1.0과 2.1.2에서 채점한 시험의 사본으로 목록, 상세
  열기, 재채점을 확인했고 점수는 바뀌지 않았습니다.

## 재현 명령

```powershell
.venv\Scripts\python.exe -m pytest
.venv\Scripts\python.exe -m ruff check src tools tests
.venv\Scripts\python.exe -m mypy src
.venv\Scripts\python.exe tools\v4_baseline.py --baseline <기준 자료 폴더>
& .\tools\build-portable-folder.ps1 -BuildNumber 25
& .\tools\verify-portable-folder.ps1 -ReleaseRoot <dir> -Smoke Both -StrictShutdown
```

기준 자료 폴더는 환경 변수 `OMR_V4_BASELINE_DIR`로도 지정합니다. 자료가 없으면 기준
회귀 테스트는 건너뜁니다. OneDrive 같은 reparse 경로 아래에서는 빌드하지 않습니다. 출력
위치 지정, 산출물 구조와 환경 준비는 [2.1.1 릴리즈 문서](2.1.1.md)를 따릅니다.
