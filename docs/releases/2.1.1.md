# OMR Grader 2.1.1

상태: 로컬 배포 후보 문서화 단계. 최종 EXE, 전체 테스트, 최종 기술 게이트의
승인을 의미하지 않습니다.

## 운영 기준

- 공식 배포물은 `OMR Grader.exe`와 `_internal\`이 함께 있는 PyInstaller onedir
  `OMR Grader\` 폴더 전체입니다. EXE만 이동하지 않습니다.
- `Data\`, `Profiles\`, `config.json`, `logs\`는 EXE와 같은 포터블 루트에 둡니다.
  `%APPDATA%`, `%LOCALAPPDATA%`, 사용자 문서 폴더로 자동 이전하지 않습니다.
- 이동·백업 전 프로그램을 완전히 종료하고 폴더 전체를 복사합니다. 내부 JSON, 세션
  폴더, 잠금 파일을 직접 편집·삭제하거나 관리자 권한 실행을 기본 해결책으로 삼지
  않습니다.
- 개발·빌드는 Windows x64, Python 3.12(`>=3.12,<3.13`), PowerShell 7.2 이상에서
  수행합니다.

## 재현 명령

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[dev,build]" -c constraints\windows-py312.lock
.venv\Scripts\python.exe -m pytest
.venv\Scripts\python.exe -m ruff check src tools
.venv\Scripts\python.exe -m mypy src
& .\tools\build-portable-folder.ps1 -BuildNumber 21
& .\tools\verify-portable-folder.ps1 -ReleaseRoot <dir> -Smoke Both -StrictShutdown
```

`py -3.12` 런처를 사용할 수 없거나 실행에 실패하면 호스트 전역 등록을 고치지
않고 다음 대체 경로를 사용합니다.

```powershell
uv venv --python 3.12 --seed .venv
.venv\Scripts\python.exe -m pip install -e ".[dev,build]" -c constraints\windows-py312.lock
```

PySide6 계열은 6.11.2, PyInstaller는 6.14.1, hooks는 2026.6으로 직접 고정되어
있습니다. 직접 고정과 제약 파일은 해시 잠금 또는 오프라인 attestation을 제공하지
않습니다.

`WorkRoot`는 새 고유 하위 폴더만 만드는 부모 경로이며 기존 파일과 출력은 보존합니다.
빌드 산출물은 다음과 같습니다. receipt는 EXE payload 밖의 외부 release 폴더에,
ZIP과 SHA-256 sidecar는 `dist` 바로 아래에 둡니다.

```text
dist\
├─ OMR-Grader-fixed21-YYYYMMDD\
│  ├─ release-receipt.json
│  └─ OMR Grader\
│     ├─ OMR Grader.exe
│     └─ _internal\...
├─ OMR-Grader-fixed21-YYYYMMDD.zip
└─ OMR-Grader-fixed21-YYYYMMDD.zip.sha256
```

receipt 형식 2는 현재 Git HEAD, 입력, 버전, 도구 버전과 payload 파일을 연결합니다.
형식 1은 `LEGACY_AUDIT_ONLY`이며 새 형식으로 재작성하지 않습니다.

OneDrive 동기화 루트와 그 아래 `dist`는 Windows Cloud reparse 경로일 수 있습니다.
빌드 가드는 모든 reparse ancestor를 거부하므로 완화하지 않습니다. 체크아웃을
일반 쓰기 가능 폴더로 복사하고, 기본 `.\dist` 또는 다음처럼 출력 위치를 지정합니다.

```powershell
$releaseRoot = 'D:\workspace\omr-grader-release'
& .\tools\build-portable-folder.ps1 `
    -DistRoot "$releaseRoot\dist" -WorkRoot "$releaseRoot\build" -BuildNumber 21
```

`-Smoke None`, 단일 `Writable`·`ReadOnly`, 비엄격 smoke의 forced-cleanup 결과는 구조
또는 부분 진단입니다.
최종 기술 게이트는 `Both`와 `-StrictShutdown`을 함께 사용합니다. 앱의 초기 화면
준비, 설정 저장·재열기, 읽기 전용 동작과 정상 종료는 빌드 검증과 별도의 앱 검증
결과로 판단합니다.

## 데이터 호환 및 고지

fixed20 세션은 열기만으로 파일을 수정하지 않으며, 새 수정 사항은 정상 저장할 수
있습니다. 새로 수동 저장하면 현재 compact state를 만들며 알려진 보정 이력만
보존하고, 알 수 없는 과거 이벤트를 만들어 내지 않습니다. 대용량 원본과 검토 JPEG는
각 세션의 `Data/<시험별 세션 폴더>/01원본스캔` 및
`Data/<시험별 세션 폴더>/02채점결과이미지`에 각각 한 번만 보관하며, generation마다
중복 복사하지 않습니다.

번들 제3자 고지는 `_internal/THIRD_PARTY_NOTICES.txt`와
`_internal/THIRD_PARTY_NOTICES_SOURCES`에 설치 패키지 기준으로 보관합니다
(Qt, PyMuPDF, OpenCV, NumPy, openpyxl, tzdata, et-xmlfile, PyInstaller). 이는
라이선스 선택이나 법적 준수 판단을 대신하지 않습니다. 공개 라이선스·계약 확인과
독립적인 실물 100페이지 스캐너 정확도 자료는 외부 조건으로 남아 있습니다.

검증 결과와 제한은 최종 검토 보고서의 날짜가 있는 사실을 사용하며, 문서만으로
최종 EXE 또는 전체 테스트·릴리즈 승인을 추정하지 않습니다.
