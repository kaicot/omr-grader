# OMR Grader 4.4.0

상태: 빌드 후보. 빌드 번호 43.

40문항 · 60문항처럼 100문항보다 짧은 답안지를 채점할 때 결과 엑셀과 정답표 요약이 답안지 문항 수를
따르도록 고친 버전입니다. 판독 엔진과 채점 규칙은 바꾸지 않았습니다.
**자료 형식 변경: 없음**(형식 1). 내부 기록은 그대로이고, 엑셀을 만드는 방식만 바뀌었습니다.

## 바뀐 점

- **결과 엑셀의 문항 열이 답안지 문항 수까지만 있습니다.** 40문항 양식이면 응답결과 엑셀, 채점결과
  엑셀의 채점결과 · 결과OX · 응답원본 · 판독 근거 탭, 정답표 탭 모두 Q1~Q40까지만 나오고 바로 뒤에
  비고가 옵니다. 예전에는 Q41~Q100이 빈칸으로 남았습니다. 이미 채점한 시험의 엑셀은 다시 채점할 때
  새 모양으로 만들어집니다.
- **'응답 엑셀로 시작'이 짧은 엑셀도 받습니다.** 일련번호 · 원본파일명 · 학번 · 이름 · Q1~QN · 비고
  (N은 1~100)이면 가져오고, 예전 100문항 모양 엑셀도 그대로 가져옵니다. Q 열이 1번부터 빠짐없이
  이어지지 않거나 비고가 맨 끝이 아니면 가져오지 않습니다.
- **정답/채점 화면의 검증 요약이 답안지 기준입니다.** 40문항 답안지에 40문항 정답표를 넣으면
  "총 출제 40문항 · 미출제(채점 제외) 0문항"으로 보입니다. 예전에는 미출제가 60문항으로 나왔습니다.
- **답안지보다 긴 정답표는 정답표를 고를 때 바로 알려 줍니다.** 예: "정답표에 41~50번이 있지만
  답안지에는 40번까지만 있습니다. 정답표에서 41~50번 행을 지운 뒤 다시 불러오세요." 이 상태로는 채점
  버튼이 눌리지 않고, 채점할 때도 같은 문구로 거부합니다.
- **다시 채점 안내 문구를 바로잡았습니다.** "기존 채점 결과는 세션의 _휴지통에 백업한 뒤" 라는 설명은
  실제 동작과 달랐습니다. 이제 "다시 채점하면 이전 결과가 새 결과로 바뀝니다. 이전 결과가 필요하면
  먼저 시험 관리의 '백업하기'를 하거나 결과 엑셀을 다른 곳에 복사해 두세요."라고 안내합니다.
- 도움말의 정답/채점 · 결과 엑셀 · 답 고치기 설명을 위 내용에 맞췄습니다.

## 주의

- 4.4.0이 만든 40문항 엑셀은 4.3.x 이하의 '응답 엑셀로 시작'으로는 가져올 수 없습니다(예전 버전은
  100문항 모양만 받습니다). 새 버전으로 만든 자료를 예전 버전으로 열지 않는 기존 원칙과 같습니다.

## 검증 결과

- 합성 40 · 60 · 100문항 답안으로 응답결과 · 채점결과 · 최종성적표 엑셀의 열 수와 색칠 범위를 확인하고,
  만든 엑셀을 다시 가져와 답이 그대로인지 확인하는 테스트를 더했습니다.
- 합성 40문항 답안지 PDF를 실제로 스캔 → 채점해 모든 엑셀이 Q40에서 끝나는지, 50문항 정답표를
  거부하는지 확인하는 통합 테스트를 더했습니다.
- 실제 졸업고사 자료(파트 2개, 24쪽): 100문항은 엑셀 모양이 예전과 같고(채점결과 106열), 50문항
  변형은 채점결과 56열 · 응답원본 55열로 Q50에서 끝납니다. 두 경우 모두 점수가 기준 기록과 일치했고
  100문항 정답표는 50문항 양식에서 거부되었습니다.
- 전체 테스트: 1853개 통과(다시 채점 문구를 확인하는 화면 테스트 1건은 새 문구에 맞게 고침).
  ruff, mypy: 문제 없음.

## 알려진 한계

- 4.3.x 이하에서 만든 100칸짜리 응답 엑셀을 '응답 엑셀로 시작'으로 가져오면, 빈 Q41~Q100 칸이
  "답안지에 없는 문항"이 아니라 "빈 답"으로 읽혀 100문항 시험으로 만들어집니다(예전과 같은 동작).
  이때는 정답표를 실제 문항 수(예: 40행)로만 만들어야 합니다. 4.4.0이 만든 엑셀은 이 문제가 없습니다.
- 한 시험에 문항 수가 다른 답안지가 섞이면(예: 40문항과 50문항), 결과 엑셀은 긴 쪽(50)까지 보이고
  정답표는 모든 답안지에 있는 문항(40)까지만 받습니다.
- [4.3.0의 알려진 한계](4.3.0.md#알려진-한계)는 그대로입니다.
