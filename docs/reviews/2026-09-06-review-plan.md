## 1. 검토 목적과 범위

현재 제품이 답안지를 정확하게 인식·채점하고, 수정·재채점·백업·복구 과정에서
시험 기록을 보존하며, 다른 PC에서도 배포·실행 가능한지 확인한다. 검증 도구가
출력하는 PASS의 의미와 실제로 확인한 동작이 일치하는지도 함께 검토한다.

최초 요청의 산출물은 검토계획이었으며, 계획 작성 당시에는 소스 수정, 테스트 실행,
재빌드, 커밋, push를 하지 않았다. 이후 사용자의 진행 지시에 따라 본 검토를 실행했고,
결과와 미확정 항목, 후속 수정 범위를 검토 보고서에 정리했다.

제품 범위는 현재 README, AGENTS, 승인된 기능 변경을 기준으로 삼는다. 로컬 구 명세와
DESIGN은 보조 자료로 사용하며, 의도적으로 제거한 학번 수정·통합성적표 기능을
미구현 결함으로 다시 계산하지 않는다.

  라이트·다크 대비, 진행·오류 안내, 키보드 조작을 점검한다.

완료 조건: 실제 EXE에서 핵심 사용 흐름이 재현되고, 종료·권한·화면·부하별 결과와

### 6단계 — 종합 보고와 수정 우선순위

- 이슈별로 심각도, 사용자 영향, 파일·줄, 재현 입력과 절차, 기대/실제 결과,
  증거, 수정 방향, 재검증 조건을 정리한다.
- 결과는 `PASS`, `FAIL`, `INCONCLUSIVE`, `NOT RUN`으로 기록한다. skip은 사유와
  대체 확인 여부를 표시하며 PASS 수에 합산하지 않는다.
- 현재 공식 verifier 판정과 이번 검토에서 입증한 운영 품질을 함께 제시한다.
  기능 완성도, 데이터 안전성, 인식·채점 정확도, 재배포 가능성, 문서 정확성을 각각 평가한다.
- P0/P1을 먼저 정리하고 P2/P3 개선 목록을 이어서 작성한다. 필요할 경우 수정 계획을
  수립하고, 수정본은 해당 변경과 새 산출물에 대해 검증하는 후속 단계로 연결한다.

완료 조건: 사용자에게 운영 가능 범위, 먼저 해결할 문제, 아직 확인하지 못한 항목을
구체적으로 보고할 수 있다. 테스트 실행 횟수나 빌드 성공만으로 검토 완료를 선언하지 않는다.

## 5. 심각도와 증거 기록

| 심각도 | 기준 예시 |
| --- | --- |
| P0 | 시험 기록의 비가역 손실, 다른 학생의 점수로 연결되는 조용한 오류, 의도하지 않은 외부 경로 삭제 |
| P1 | 확정 입력 오채점, 주요 백업·복구 불능, 정상 환경에서 필수 흐름 사용 불가, 새 배포 재현 불가 |
| P2 | 회피 가능한 오류, 특정 환경의 성능·접근성 문제, 검증·문서의 불완전한 보장 |
| P3 | 낮은 영향의 안내·정리·유지보수 개선 |

심각도는 재현된 영향으로 정한다. 환경 때문에 실행하지 못한 검사는 제품 결함으로
단정하지 않고 INCONCLUSIVE와 환경 조건을 기록한다.

각 실행 증거에는 실행 시각, HEAD·diff, 명령, 환경, 입력·프로필 해시, EXE·ZIP 해시,
예상값, 실제 결과, 종료코드, 제한사항을 포함한다. 저장 위치는
`artifacts/review-20260906/<attempt>/`를 사용한다. 테스트용 실행 폴더는 동기화 경로
밖에 별도로 만들고 해당 시도의 복사본·프로세스·ACL만 관리한다.

실제 학생 자료가 필요하면 우선 합성·비식별 표본으로 진행한다. 학생 원본, 기존
시험 세션, 기존 배포본은 보존하고 공개 보고서에는 식별정보와 원본 스캔을 넣지 않는다.
